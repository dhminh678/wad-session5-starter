- **Out-of-scope production considerations:**
  - **Resilience to partial stock endpoint failures:** In versions A, B, and C, `Promise.all` uses fail-fast semantics; if a single `/api/stock/:id` returns 404 or 500, the entire stock calculation throws and fails. In production, using `Promise.allSettled()` would allow displaying the total for available items and gracefully logging missing items.
  - **Cancellation of stale in-flight requests on mode switch / retry:** If a user clicks Retry or changes test conditions while previous stock requests are still in flight, responses from the old fetch could theoretically resolve and mutate state. Introducing an `AbortController` to cancel pending requests when `load()` is re-invoked would eliminate this edge case.
  - **Client-side stock caching:** Each page load triggers 8 separate HTTP requests to `/api/stock/:id`. A production client would benefit from caching stock data in memory or relying on HTTP caching headers (`Cache-Control`, `ETag`) to avoid redundant network round-trips.
